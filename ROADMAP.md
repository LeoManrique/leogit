# leogit — Roadmap

What's shipped lives in [DESIGN.md](DESIGN.md). This file tracks **what's next**. Items are added as they're discovered; check a box only when it ships.

## Recently completed

- [x] **The native client got the row context menus — every per-item action the Tauri client had, and none it didn't.** An audit of both clients found the gap was exactly two menus: right-clicking a changed file and right-clicking a commit. Nothing else was missing (the branch row's delete already ships as a toolbar-menu submenu, and the Tauri diff viewer's per-line selection is dead code in that client too), and seven core functions that had shipped in Tauri for months — `discard_files`, `ignore_paths`, `append_to_gitignore`, `reveal_path`, `open_path`, `checkout_commit`, `undo_last_commit` — had simply never been exported to the bridge. **File rows** now offer Discard Changes… (confirmed, and the dialog says which of the two things will happen — restored from HEAD, or moved to the Trash because it was never committed), Ignore File / Ignore All \*.ext Files, Copy File Path / Copy Relative File Path, and Reveal in Finder / Open with Default Program (disabled for a deleted file). **Commit rows** offer Amend Last Commit…, Undo Last Commit, Check Out Commit… (confirmed, with the detached-HEAD warning), Copy SHA, and Copy Tag. Amend brings the composer's whole amend mode with it: the commit's message and its co-author trailers seed the draft, a notice band with *Stop Amending* appears above the fields, the button becomes *Amend Commit*, and the must-check-files gate relaxes so a message-only amend works on a clean tree. Two things came out better than the port: the composer moved out of the Changes tab into the repository screen, because a tab switch rebuilt that pane and silently discarded any in-progress message (amend, which starts in the *History* tab, made the bug unavoidable); and HEAD is identified by `status.head_sha` rather than by the row's index, which is the Tauri list's own bug — after its window slides, row 0 is no longer HEAD but still offers to amend it. Two new bridge tests cover the discard/ignore pair and the checkout/undo pair against real repositories. Zero-warning build; 25 bridge tests.

- [x] **The repo switcher's filter actually filters, and ranks what it finds.** Typing `llm` listed all fourteen repositories. The rule ported from the Tauri picker treats the query as a subsequence of the *full path*, and every row shares one — `/Users/leo/Dev/LeoManrique/Desktop/…` — so `llm` was satisfied by the `l` of `leo`, the `l` of `LeoManrique`, and that word's `m` before reaching the repo name at all. The two halves of a path are now searched by how much signal each carries: the name keeps the loose scattered match (`gpm` still finds `git-projects-manager`), while the path must contain the query contiguously and only below the scan folder holding it, so the shared ancestry can't match anything. Results are also ranked — exact name, prefix, substring, initials, subsequence, then path — with the previous active-first / most-recently-used order surviving only as the tie-break inside a tier. That half matters as much as the filtering: Return opens the first row, and pinning the active repo there meant Enter re-opened the repo already on screen instead of the one just typed. **Both clients are fixed**, by one rule with two implementations — `RepoSearch.swift` and `repoSearch.ts` — diffed against each other over the real repo list and identical across twenty queries (`llm` 15 → 1, `leo` 15 → 5 with the three `leo*` repos leading, and `users` / `desktop` now correctly matching nothing). The Tauri side gained more than parity: its two pickers had hand-rolled a matcher each — the startup picker searched *only* the path — and now share this one, while the expanded scan folders they need moved into the config store instead of being fetched twice in `App.svelte`. Zero-warning builds on both; svelte-check clean. Still missing natively, and worth a follow-up: ↑/↓ to pick a row other than the first, which the Tauri pickers have.

- [x] **The terminal dock's header is a real macOS accessory bar.** It was a hand-styled row — a `.plain` text button beside `.borderless` icon buttons, all forced to a secondary foreground — which is precisely why it read as flat: those styles give no hover or press feedback, so the controls looked like static glyphs painted on a strip rather than things you could click. The whole row now takes `.buttonStyle(.accessoryBar)`, the control class AppKit draws as the *recessed* bezel behind every scope bar in the system (Finder's search scopes, Safari's favourites bar), so hover, press, and selected states arrive from the platform and nothing here paints its own — the same lesson as the toolbar round: use the system control, don't imitate it. The shell name became a button-styled `Toggle`, so the strip carries the panel's open state the way a scope bar carries a selected scope, and its binding routes through `toggle()` so the lazy first PTY spawn still happens; the glyph moved from the older generic `terminal` to `apple.terminal`, the current-era symbol; the three right-hand buttons are `Label`s rendered icon-only, which finally gives them accessibility names to go with their tooltips; and the strip is pinned at the 28 pt STYLE.md always specified, with the forced caption font and secondary foreground dropped so the style sets its own typography. Two findings shaped what *didn't* change: macOS has no bottom-toolbar placement at all (`.bottomBar` is `@available(macOS, unavailable)` in the macOS 26 SDK), so hand-assembling the strip is the only option — the win is that it's assembled from stock controls; and the HIG restricts Liquid Glass to the navigation layer, so a content-layer bar keeps its `.bar` material rather than gaining a glass effect. The emulator below also gained a small gutter (8 pt horizontal, 6 pt vertical) over the same black it paints: SwiftTerm's layer has no inset API and draws edge to edge, so the first column sat against the strip above and ran into the window's rounded bottom corner, which clipped it. Swift-only; zero-warning build.

- [x] **⌘P runs whatever the sync button is offering, and the menu bar says what that is.** The adaptive toolbar button had no keyboard route at all, so on a repo with no remote there was no way to Publish without reaching for the mouse. It now has a menu-bar home — **Repository ▸ Publish / Publish Branch / Pull / Push / Fetch (⌘P)** — where the item renames and disables itself along with the button, because a shortcut whose menu item lies about what it does is worse than no shortcut. Mechanically the ladder became `SyncProposal`, a pure type over the status that both views read, and the button gained a single `perform()` shared by its face and the split button's primary action; the repository screen publishes the proposal as a `SyncCommand` through `focusedSceneValue`, read back in a `Commands` struct with `@FocusedValue` — the one case where a focused value beats this app's `leogitRefreshRequested` notification pattern, since a notification can fire an action but can't title it. Two placement facts carried the round: the value must be published from the **window content** — a focused scene value set on a toolbar-hosted view never reaches the scene, which left the first attempt's menu item permanently disabled — and the menu item's closure posts a notification back to `SyncControls` rather than acting itself, so the publish sheet, error alert, and busy guard stay on the same path a click takes. Swift-only; zero-warning builds.

- [x] **The commit composer got the Tauri pair's field behaviors, and every list column yields more room to its diff.** The left column is now one proportion across both tabs (ideal 280 pt, max 420 pt, down from 320/520): the changes checklist plus composer and the commit history are the same width, so the divider doesn't jump when switching tabs, and inside the History detail the changed-file column is tighter still (240/360) since those rows carry only a path. The description swapped its growing `TextField` for a `TextEditor` at a fixed five-line height with a real scrollbar past it — the vertical-axis `TextField` scrolls only with the caret, which is also why the summary became `Design/WheelScrollableTextField`: the stock `NSTextField` wrapped to forward scroll gestures to its field editor, the AppKit counterpart of the Tauri composer's wheel→`scrollLeft` handler, so a long generated summary can be swiped through. And the single-file auto-summary is ported: with exactly one file checked, the summary placeholder reads "Create/Delete/Update \<file\>" and an empty submit commits it verbatim (`CommitStore.autoSummary`, the GitHub Desktop rule the Tauri composer follows). Swift-only; zero-warning build.

- [x] **The toolbar reads as two edge clusters — where-am-I leading, counts + action trailing — with zero custom drawing.** The macOS 26 toolbar decides capsule grouping by `ToolbarSpacer` boundaries: adjacent items with no spacer between them share one glass background, so the repo switcher and branch menu sit as two plain adjacent `ToolbarItem`s, and a `ToolbarSpacer(.flexible)` pushes the sync cluster to the trailing edge — needed because removing the title also removed the area that used to separate leading from trailing (`ControlGroup`, `ToolbarItemGroup`, and the `.navigation` placement were each tried for the merge and all rendered separate chips). Each chip shows icon and text: the switcher carries the repo name and the branch menu the branch name (`.labelStyle(.titleAndIcon)`; toolbar labels are icon-only by default), with the branch menu's chevron hidden (`.menuIndicator(.hidden)`) so the pair reads consistently — the repo chip's popover never had one. The toolbar title — pure duplication once the chip names the repo — is removed with `.toolbar(removing: .title)` while `navigationTitle` keeps naming the window for Mission Control; the old subtitle's exceptional states live on the branch chip's own label ("Detached at abc1234", "main · merging"). The ahead/behind counts are standalone `↑N ↓N` secondary text immediately left of the adaptive sync button — its toolbar item hides its glass background (`sharedBackgroundVisibility(.hidden)`, the pattern Apple's docs use for an informational build-status item) so it reads as status, not a control — with the spelled-out counts in its tooltip. The sync button's label is normalized to `.fontWeight(.regular)` — the trailing action region otherwise emphasizes it (bold text, heavier symbol), which read as a different design family than the chips. Repo name, branch name, and counts each appear exactly once. Swift-only; zero-warning builds.

- [x] **Native indicators: a real count pill on the Changes tab, the Tauri push plate in the commit list — and the sync button deliberately left stock, carrying no pill at all.** The user's screenshots showed the adaptive sync button as a bare arrow (the macOS toolbar renders labels icon-only by default; `.labelStyle(.titleAndIcon)` restored the state word) and no working-tree count anywhere. A first pass folded the counts into the text — "Push (1)", "Changes (1)" — rejected on sight, and rightly: parens in a control face read as an afterthought, not an indicator. The real fix is a shared `CountBadge` stadium pill — one component where the Tauri client hand-rolls two near-identical pills — on the Changes tab with the Tauri badge's exact semantics: the full working-tree list including untracked and conflicted files, visible from any tab, hidden at zero, never capped. Hosting that pill meant replacing the stock segmented picker with `RepoTabBar`, the left-aligned accent-underline tab strip STYLE.md had specified all along — so rejecting the parens also moved the native client onto the design contract's own tab treatment. The commit list's not-yet-pushed marker grew from a bare 9 pt glyph into the Tauri row's treatment: a 16×16 rounded-square plate sharing the tag chips' height and radius, so the row's indicator cluster reads as one family instead of a stray arrow. The sync button is the one place the pill could not follow: macOS bridges a toolbar button's or menu's label to a system control that renders only its text and icon, no system API badges a macOS toolbar item (the 26 SDKs' toolbar `.badge` is iOS-only), and a hand-built split button — plain segments, hand-drawn hover highlights — went through several rounds before being rejected as visibly non-native. It reverted to the stock `Menu`+`primaryAction` control, and the pending count lives where the platform can show it: the window subtitle (`↑N ↓N` beside the branch), the Changes tab pill, and the button's tooltip. Swift-only change; zero-warning builds.

- [x] **The native toolbar's three sync-area controls became one adaptive button, and the Refresh button is gone.** The user flagged the redundancy — Pull, a Push split menu hiding Fetch, and a Refresh button whose reason to exist was unclear next to the 2 s poll. The answer is GitHub Desktop's model (studied in the inspo fork alongside the Tauri header) running on LeoGit's own workflow machinery, all of which is unchanged: a strict precedence ladder shows the one action that makes sense now — detached (disabled) → *Publish* (no remote, plain button → sheet) → *Publish Branch* → *Pull (N)* → *Push (N)* → *Fetch* when in sync — where pulling outranks pushing so a diverged branch proposes the step that must come first, the chevron menu always offers Fetch (no longer filed under *push* options), and *Force Push (with Lease)* keeps its diverged-only, confirmed, menu-only placement, which the ladder makes appear exactly in the pull state like GitHub Desktop. The Refresh button's four real jobs moved to better homes instead of a button: the forced log refetch was already covered (every amend/rebase/checkout moves `head_sha`, which the poll watches); branch-list freshness is now automatic (the menu reloads its list on open, and the poll reloads it when HEAD moves — GitHub Desktop has no branch staleness problem for the same reason); error surfacing is now the poll's own (three consecutive failed ticks raise the banner, recovery clears it, and a poll-owned flag keeps a background tick from ever sweeping away an explicit action's error); and the full visible reload survives as **View ▸ Refresh (⌘R)**, posted to the main window over the same notification pattern the Settings window uses. Swift-only change; verified with a zero-warning `xcodebuild` and no Rust rebuild needed.

- [x] **The native History tab shows full commit detail.** It was a bare four-column table — no way to see what a commit actually changed. It is now the Tauri layout end-to-end: the commit list on the left (two-line rows with tag chips, the not-yet-pushed ↑ from `unpushed_shas`, author · relative time, and paging — the list appends another `get_log` page whenever its last row scrolls into view, where it previously stopped silently at 100 commits), and the selected commit's detail on the right: summary with the `get_commit_stats` +/− totals, the full message body (scrollable past 140 pt, height-measured so a short body hugs its text), author + email + absolute date, the full SHA with a copy button, the files-changed count, and the commit's changed files beside each file's diff at that commit. Reuse over rebuild, per request: the file rows were extracted from the Changes tab into a shared `ChangedFileList` (the checkbox arrives through a builder slot, so History gets the same rows without one), and the existing diff viewer gained a `DiffTarget` — `.workingTree(epoch:)` or `.commit(sha:)` — that selects both the raw-diff read (`get_commit_diff`, new to the bridge with `get_commit_files`/`get_commit_stats`) and the tokenizer's blob source in one value, so commit diffs get the same syntax colour, intra-line highlights, and binary/empty states as working-tree ones, read at the commit's own trees. Fixed along the way in core: `get_commit_diff` now passes `--root` like its two siblings — without it, a `log.showRoot=false` user saw the first commit's file list populate while every diff came back empty. One deliberate improvement over Tauri: a failed file-list read shows an error state instead of silently rendering as "no files". Verified: zero-warning `xcodebuild`; 121 core + 23 bridge tests (new: the root-commit regression, and a commit-detail flow test that gives `BlobSource::Commit` its first coverage anywhere — rename `orig_path` crossing the bridge, binary files counting zero in stats, tokens read at the commit); clippy-pedantic clean with core's 183 baseline untouched.

- [x] **The native changes list shows each file's path on one line.** It stacked the filename over its directory in a two-line row, which cost vertical space in the densest list in the app and still cut the directory off arbitrarily. It now renders the whole repo-relative path on a single line through a new shared `PathText`, ported from the Tauri client's component rather than reinvented: the directory (muted) gives way first, collapsing to a `…/` bridge but never below a first-letter hint — so a nested file can't be mistaken for a root file — and only then does the filename middle-truncate. SwiftUI's `.truncationMode(.middle)` can't express that (it doesn't know which half of a path identifies the file), so the view binary-searches the widest fit, measuring with the same `NSFont` it draws with. The port was validated by diffing its output against the Svelte original's over every path/budget pair, so the two clients shorten paths identically.

- [x] **The repo switcher's list is populated before it opens.** The first open of the native switcher showed only the active repo and looked correct only on a *second* open: nothing ran discovery until the popover's own `.task` fired, so the cold filesystem walk started at the moment the list was already on screen (the row list is `@Observable`, so rows would have appeared in place — but not before the popover was closed and reopened). Three fixes, none of which delay opening a repo. **(1)** A `.task` on the repository screen primes `refreshDirectory()` when that screen appears, running alongside the repo-open chain rather than inside it; it is unkeyed, because the walk spans every repo and belongs to the screen's lifetime, not a repo's — the popover still refreshes on open, so a freshly cloned repo appears without a restart. **(2)** A pass now publishes **twice**: the shared MRU first (a small JSON read, and precisely the repos the user cycles between), then the walk's result — with the previous walk's output retained so the interim publish can never drop discovered rows, and the persisted MRU unioned with the local one so a refresh racing `noteOpened`'s not-yet-landed write can't make the just-opened repo vanish. Concurrent callers (prime + popover, or the tier scheduler bootstrapping an empty MRU — which no longer loads the MRU its own way) await the single in-flight `Task` instead of walking the tree twice. **(3)** `discover_repos` became the bridge's second **async-over-`spawn_blocking`** export, joining `repo_sync_status`: core's walk is synchronous and stats whole directory trees, so at depth 4 over several roots it was parking one of Swift's cooperative threads (one per core) for its whole duration. Also, the popover distinguishes *still looking* from *found nothing* — the diagnosable "no repositories found — we searched…" state is only correct once a pass has finished. Verified: zero-warning `xcodebuild`, 120 core + 22 bridge tests (the discovery test is now `#[tokio::test]`), clippy-pedantic clean with core's 183 baseline untouched.
- [x] **Native gh-publish + a Pull Requests tab + terminal exit codes (ninth Phase-2 chunk of the SwiftUI plan) — the gh surface closed, and the first roadmap item fixed in both clients at once.** *Publish:* `gh_publish_repo` exported (core-async like `gh_clone`; no listener — `gh repo create` streams nothing parseable) and the toolbar's remote-less state became a real **Publish** button + sheet (name seeded from the folder, private by default, gh's errors inline with fields preserved for retry), claiming a new `.publish` case in the same single `activeOperation` slot as push/pull — Tauri's `'publish'` op, so every background loop pauses. *Pull requests:* the PR surface was **re-derived in core** — the Tauri PR view was retired before the port, so `list_prs`/`get_pr_checks`/`create_pr`/`checkout_pr` were rebuilt from the old TUI's shape under the current conventions (`run_timed` + 20 s/600 s budgets, `stderr_or` fallbacks — now shared by every gh error path — `current_dir` because `gh pr` has no path flag, pure `parse_pr_list`/`parse_pr_checks` pinned by tests, incl. the load-bearing quirk: `gh pr checks` exits non-zero while anything is pending/failing but still writes valid JSON, so stdout parses first) and shipped as a native third tab: Open/Closed/Merged/All segments, state-dot list, detail pane with review decision, churn, description, and per-PR CI checks cached on selection, plus Checkout (fork-aware, working-tree errors verbatim), Open on GitHub, and a create sheet whose title seeds from the head commit's summary (the native `--fill`). *Terminal exit codes* (the ROADMAP item, both clients): the reader thread now **reaps the child** with `child.wait()` after EOF — session out of the map first, so the instant post-EOF wait can block nobody, and `close_terminal` no longer removes the entry (the reader owns teardown and needs the child for the status; both clients now keep the dead terminal on screen with `[Process exited with code N]` on a non-clean exit (VS Code's behavior — a broken `.zshrc` no longer flashes its error away) and close the panel as before on code 0. Also reaps the zombie every session used to leave. *Follow-up from review:* the tab is **opt-out** — a new shared `show_pull_requests` config field (`#[serde(default)]` on, pinned by test; mirrored in the bridge and the Tauri TS type, whose settings overlay round-trips it untouched) behind a *Pull Requests* Settings section; off hides the tab and with it every `gh pr` call, and the tab also hides itself for repos with no remote. Applies live across scenes via a `leogitConfigDidSave` notification (the Settings window and main window share no store), with the selection snapping back to Changes if the tab vanishes under it. Verified: zero-warning `xcodebuild`, **120 core + 22 bridge tests** (PR parsing incl. ghost authors + the checks quirk; publish/create-PR guards firing before `gh` spawns; the real-PTY suites now asserting `exit 7` → code 7 and kill → non-clean; the old-config default), clippy-pedantic clean in bridge and host with core's 183 baseline untouched, svelte-check 0/0, Tauri host builds clean.

- [x] **Native embedded terminal (seventh Phase-2 flow of the SwiftUI plan) — the last core flow, closing the port plan's final open question.** The native client gains the Tauri terminal, behavior-for-behavior: an always-visible header strip under the content, ⌘` (or the header) toggling the fixed 280 pt panel, the PTY spawned lazily on first expand — the shared `terminal_shell` preference read fresh per session, resolved by core to the best shell on the machine, with the shell that *actually* launched named in the header — minimize hiding the view but keeping the shell running, **+** replacing the session, **✕** killing it, a self-exiting shell collapsing the panel, repo switches killing the session so shells never leak, and a failed spawn printed into the emulator in red ANSI. - [x] **Native background sync + repo switcher with indicators (sixth Phase-2 chunk of the SwiftUI plan).** Two features in one chunk, as requested. *Background parity:* the native client now runs the Tauri client's whole refresh machinery — the 2 s status poll (silent: no progress-bar flash, history refetched only when `head_sha` moved, the diff-reload epoch bumped only on real change), auto-fetch on the shared `auto_fetch`/`fetch_interval_ms` config, an app-activation resync (fetch + silent refresh + unconditional diff re-read + a 30 s-throttled badge catch-up — the `resyncOnActive` the Tauri client hangs off DOM focus/visibility events), and a ported `ConnectivityBreaker` (2 failures → 30 s backoff doubling to 5 min). Verified: zero-warning `xcodebuild`, 117 core + 15 bridge tests (discovery against a temp tree; the badge summary through no-remote → in-sync → dirty → ahead → behind-only-after-fetch), clippy-pedantic clean in bridge and host with core's baseline untouched.

- [x] **Native AI commit messages (fifth Phase-2 flow of the SwiftUI plan).** The composer gains the Tauri client's Generate flow: a provider pop-up (Claude / Ollama) and a **Generate** button (⌘G — window-wide, where the Tauri shortcut only fires with a composer field focused) that sends the checked files' combined diff (`get_selected_diff`) to the provider and fills summary + description from the pre-split `CommitMessage` — overwriting the drafts, with failures inline in the composer's shared error slot, same wording as the Svelte composer. Config parity without a settings UI: the one mapping the Tauri client keeps in TypeScript (config → `AiProviderConfig`) moved into the bridge as `load_ai_config`, compile-checked against core, and the provider picker persists through `save_ai_provider`'s validated read-modify-write of the whole config — so both clients honour the same `config.toml` and an unknown value can never be persisted. - [x] **Check out remote branches as local tracking branches.** Picking a branch from the dropdown's *Remote Branches* section (e.g. `origin/feature`) used to run `git checkout origin/feature --`, which — because the trailing `--` disambiguates the ref as a commit-ish — left the user in **detached HEAD** instead of on a usable branch. `switch_branch` ([core/src/git.rs](core/src/git.rs)) now probes with `git show-ref --verify --quiet`: a name that isn't a local branch (`refs/heads/<name>`) but is a remote one (`refs/remotes/<name>`) routes through `checkout_tracking_branch`, which derives the local name by dropping the remote prefix (`origin/team/x` → `team/x`, matching `git switch`'s DWIM) and runs `git checkout -b <local> --track <remote>`. - [x] **Offline / flaky-connection resilience — the app no longer hangs without a network.** Root cause: every network git command (`fetch`/`pull`/`push`/`clone`/`repo_sync_status`/`delete_remote_branch` + the four `gh` commands) ran *synchronously on the Tauri main thread with no timeout*, so when offline a single blocked `git fetch` froze the window while the 30 s auto-fetch, the tiered scheduler, and on-refocus fetches kept piling on more. Fixed in three layers: (1) all network commands are now `#[tauri::command(async)]` so they run on a worker thread, never the UI thread; (2) a new `process::run_timed` kills any subprocess that outlives its budget (background badge fetches 12 s, user transfers 600 s), and `git_net_cmd` bakes in SSH `ConnectTimeout`/`BatchMode` + HTTP low-speed timeouts so git itself aborts a dead connection fast (unit-tested via `run_timed_kills_a_hung_child_promptly`); (3) a frontend connectivity service ([services/connectivity.ts](apps/tauri-app/src/lib/services/connectivity.ts)) gates *automatic* fetches on `navigator.onLine` + a consecutive-failure circuit breaker (exponential backoff 30 s → 5 min), so we stop hammering an unreachable remote and resume instantly on the OS `online` event or the next successful manual action. `repo_sync_status` now returns a `fetched` flag so the breaker distinguishes a real failure from a no-remote repo. No new UI surface — by design the app just degrades gracefully and recovers on its own.

## What's next


- [x] **Claude CLI failures surface their real error.** A non-zero exit with an empty stderr (the CLI puts API/auth errors in the stdout JSON envelope) used to show a bare "Claude CLI failed:". `claude_failure_message` now falls back stdout-envelope → stderr → stdout → exit status, so the message is never blank. Covered by unit tests plus an `#[ignore]`d fake-CLI e2e test in `commands::ai::tests`.
- [x] **Windows: make the embedded terminal actually usable.** The terminal launched Windows PowerShell with a broken `PATH` and most commands failed. Root cause: `start_terminal` copied `std::env::vars()` over the environment `CommandBuilder` had already assembled — discarding the `HKLM`+`HKCU` registry merge portable-pty performs and replacing it with the parent's. Launched from Git Bash that parent `PATH` is MSYS-style (`/usr/bin`, `/c/Program Files/...`), which Win32 cannot resolve at all. Removing the copy restores the same `PATH` Explorer and Windows Terminal give their children; `session_env` now returns only deliberate additions and is covered by `session_env_never_overrides_path`. Alongside it: **shell choice** — new [core/src/shell.rs](core/src/shell.rs) probes for Git Bash (registry install root, launched `--login -i` with `CHERE_INVOKING=1`), pwsh, Windows PowerShell and cmd, exposes them via `list_shells`, and persists the pick as `config.terminal_shell` (Settings → Terminal); an uninstalled preference falls back instead of failing. **UTF-8 corruption** — output was decoded per 4 KiB chunk with `from_utf8_lossy`, so any multi-byte character straddling a read boundary became a permanent U+FFFD; a stateful `Utf8Decoder` now holds the truncated tail. **Rendering** — xterm is told `windowsPty {backend, buildNumber}` (via the new `terminal_pty_info`) so reflow is enabled, and the `ResizeObserver` is debounced 80 ms so dragging the panel no longer triggers a PSReadLine repaint per frame. Terminal IPC moved behind `terminalApi` in `api/commands.ts`; `lazy_static` was replaced with `std::sync::LazyLock` and dropped as a dependency.

- [x] **Windows: `git init` produced `master`, not `main`.** `init_repo` probed `git config --get init.defaultBranch` across *all* scopes to decide whether the user had a preference. Git for Windows ships `init.defaultBranch = master` in its **system** config (`C:/Program Files/Git/etc/gitconfig`), so a vendor default was read as a deliberate choice and every repo LeoGit created on Windows landed on `master`. The probe now runs with `GIT_CONFIG_NOSYSTEM=1`, restricting it to the global and local scopes a user actually sets. This is what `init_repo_names_the_default_branch` had been failing on.
