# leogit — Roadmap

What's shipped lives in [DESIGN.md](DESIGN.md). This file tracks **what's next**. Items are added as they're discovered; check a box only when it ships.

## Recently completed

- [x] **Checkout commit (detached HEAD).** Right-click any commit in History → **"Checkout commit"** (disabled on the current HEAD) runs `git checkout <sha>`, landing on a detached HEAD — mirroring GitHub Desktop. A confirmation dialog ([CheckoutCommitConfirm.svelte](tauri-app/src/lib/components/CheckoutCommitConfirm.svelte)) first explains the detached-HEAD consequence. New backend command `checkout_commit` ([commands/git.rs](tauri-app/src-tauri/src/commands/git.rs)) surfaces git's "local changes would be overwritten" refusal verbatim instead of losing work. The detached state is now first-class: `get_status` parses `detached` (from `# branch.head (detached)`) and `head_sha` (free, from `# branch.oid`), and the Header ([Header.svelte](tauri-app/src/lib/components/Header.svelte)) shows `On <short-sha>` + a `DETACHED HEAD` marker and suppresses Push/Pull while detached. The user reattaches by picking a branch (`switch_branch`). Covered by `checkout_commit_detaches_then_branch_reattaches`, `checkout_commit_fails_when_local_changes_would_be_overwritten`, and `get_status_reports_branch_and_head_sha`.
- [x] **Unpushed-commit markers on unpublished branches.** The History view's up-arrow ("not yet pushed") never appeared on a branch with no upstream — clone `main`, branch off, commit, and leogit showed no arrows at all, while GitHub Desktop marks the new commit and leaves the shared base unmarked. Cause: `get_status` only built `unpushed_shas` when `ahead > 0` with a resolved upstream, and `ahead` stays 0 on an unpublished branch. Fix in [commands/git.rs](tauri-app/src-tauri/src/commands/git.rs): when there's no resolvable upstream but the repo has remote-tracking refs, fall back to `git rev-list HEAD --not --remotes` (local commits not on **any** remote). The frontend was already wired ([CommitList.svelte](tauri-app/src/lib/components/CommitList.svelte) badge + [MainLayout.svelte](tauri-app/src/lib/views/MainLayout.svelte)); it just had nothing to render. Covered by the `unpushed_shas_marks_local_commits_on_unpublished_branch` Rust test.
- [x] **Check out remote branches as local tracking branches.** Picking a branch from the dropdown's *Remote Branches* section (e.g. `origin/feature`) used to run `git checkout origin/feature --`, which — because the trailing `--` disambiguates the ref as a commit-ish — left the user in **detached HEAD** instead of on a usable branch. `switch_branch` ([commands/git.rs](tauri-app/src-tauri/src/commands/git.rs)) now probes with `git show-ref --verify --quiet`: a name that isn't a local branch (`refs/heads/<name>`) but is a remote one (`refs/remotes/<name>`) routes through `checkout_tracking_branch`, which derives the local name by dropping the remote prefix (`origin/team/x` → `team/x`, matching `git switch`'s DWIM) and runs `git checkout -b <local> --track <remote>`. The local-first guard keeps a slash-containing local branch from being misread as remote, and a name collision falls back to switching to the existing local branch rather than failing. Mirrors GitHub Desktop's `getBranchCheckoutArgs`; no frontend/API change (the command signature is unchanged). Git semantics verified against a throwaway repo (detached-HEAD repro + all three fix paths).
- [x] **Embedded (nested) git repository support.** A folder with its own `.git` — which `git status` reports as a single untracked directory entry and never recurses into — used to fail to commit with the cryptic `staging produced no changes`, because `update-index --add` silently ignores directory paths. Root cause fixed in [commands/git.rs](tauri-app/src-tauri/src/commands/git.rs): additions now stage through `git add` (new `git_add` helper), which commits the nested repo as a **gitlink** (mode 160000) like the git CLI, while removals keep using `update-index --force-remove`. `get_status` flags such entries `embedded: true` (untracked + trailing-slash path under `-uall`); the UI renders a blue ↪ link badge ([FileList.svelte](tauri-app/src/lib/components/FileList.svelte)) and pops a confirm modal ([EmbeddedRepoConfirm.svelte](tauri-app/src/lib/components/EmbeddedRepoConfirm.svelte)) — "Commit nested repository as a link?" — before committing, since a gitlink (not the folder's files) is a surprising outcome. Fires every time (embedded repos are rare and disappear from Changes once committed). Covered by the `commits_embedded_repo_as_gitlink` Rust test. Same bug exists in GitHub Desktop, which just dumps `git status` and dead-ends.
- [x] **Dirty-submodule commit guard.** A tracked submodule dirty *inside* but whose recorded commit hasn't moved has nothing the parent can stage, so committing it dead-ended with `staging produced no changes` (GitHub Desktop instead disables the row and explains it). `get_status` now flags these `submodule_dirty: true` by reading the porcelain-v2 `sub` field (`S<c><m><u>` with `c == '.'` and `m`/`u` set — `is_dirty_submodule` in [commands/git.rs](tauri-app/src-tauri/src/commands/git.rs)); a moved pointer (`c == 'C'`) stays committable. The UI makes the entry non-selectable everywhere `selectedFiles` is written ([MainLayout.svelte](tauri-app/src/lib/views/MainLayout.svelte) via `isCommittable`), renders a muted ↪ badge + disabled checkbox with a tooltip ([FileList.svelte](tauri-app/src/lib/components/FileList.svelte)), and shows a "Submodule changes" panel in the diff pane instead of the opaque `Subproject commit …-dirty` line — so the failing path is unreachable. Covered by the `classifies_only_unstageable_dirty_submodules` and `parses_dirty_submodule_flag_from_ordinary_entry` Rust tests.
- [x] **Changes-tab file-row context menu.** Right-clicking a changed file opens a GitHub-Desktop-style menu ([FileList.svelte](tauri-app/src/lib/components/FileList.svelte) + [services/fileActions.ts](tauri-app/src/lib/services/fileActions.ts), reusing the `ContextMenu` primitive): **Discard Changes…**, **Ignore File** / **Ignore All .ext Files**, **Copy File Path** / **Copy Relative File Path**, **Reveal in Finder/Explorer/File Manager**, **Open with Default Program**. Right-clicking inside a multi-row selection collapses the menu to a single **Discard N Selected Changes…**. Discard always confirms ([DiscardConfirm.svelte](tauri-app/src/lib/components/DiscardConfirm.svelte)) then reverts tracked files to HEAD and moves never-committed files to the **OS Trash** (recoverable) via the new `git::discard_files` (classified by a `head_paths` `ls-tree` probe + the `trash` crate). Backend also added `git::append_to_gitignore` (dedup + newline-safe append) and `os::reveal_path` / `os::open_path` (bounded, platform-specific launchers in [commands/os.rs](tauri-app/src-tauri/src/commands/os.rs)). Covered by Rust tests (`discard_*`, `head_paths_*`, `append_to_gitignore_*`). Remaining context-menu items deferred: **Ignore Folder** and **Open in Editor** (needs the external-editor picker below).

- [x] **Offline / flaky-connection resilience — the app no longer hangs without a network.** Root cause: every network git command (`fetch`/`pull`/`push`/`clone`/`repo_sync_status`/`delete_remote_branch` + the four `gh` commands) ran *synchronously on the Tauri main thread with no timeout*, so when offline a single blocked `git fetch` froze the window while the 30 s auto-fetch, the tiered scheduler, and on-refocus fetches kept piling on more. Fixed in three layers: (1) all network commands are now `#[tauri::command(async)]` so they run on a worker thread, never the UI thread; (2) a new `process::run_timed` kills any subprocess that outlives its budget (background badge fetches 12 s, user transfers 600 s), and `git_net_cmd` bakes in SSH `ConnectTimeout`/`BatchMode` + HTTP low-speed timeouts so git itself aborts a dead connection fast (unit-tested via `run_timed_kills_a_hung_child_promptly`); (3) a frontend connectivity service ([services/connectivity.ts](tauri-app/src/lib/services/connectivity.ts)) gates *automatic* fetches on `navigator.onLine` + a consecutive-failure circuit breaker (exponential backoff 30 s → 5 min), so we stop hammering an unreachable remote and resume instantly on the OS `online` event or the next successful manual action. `repo_sync_status` now returns a `fetched` flag so the breaker distinguishes a real failure from a no-remote repo. No new UI surface — by design the app just degrades gracefully and recovers on its own.

- [x] **`leogit` shell command — open a repo from the terminal.** `install.sh` now also installs a `leogit()` shell function into the user's login shell, detected from `$SHELL` (zsh → `~/.zshrc`; bash → `~/.bashrc` on Linux / `~/.bash_profile` on macOS; fish → an autoloaded `~/.config/fish/functions/leogit.fish`; unknown shells get a printed snippet). It's written inside an idempotent `# >>> leogit >>>` marker block so re-installs replace rather than stack. `leogit [dir]` resolves the directory and opens that repo in LeoGit — macOS via `open -n --args` (a fresh process whose argv the single-instance plugin forwards), Linux via the PATH wrapper, backgrounded. The app gained command-line repo opening backed by `tauri-plugin-single-instance` ([commands/launch.rs](tauri-app/src-tauri/src/commands/launch.rs)): a cold start stashes the resolved git path (`set_pending_open_repo`) for the frontend to claim on mount (`take_pending_open_repo`); a second invocation focuses the existing window and forwards the path as an `open-repo` event (`handle_second_instance`), handled live by `MainLayout` (reusing `handleSwitchRepo`, adding the repo to the list if it's outside the scan paths) or by `App.svelte` in the pre-main phases. Paths are canonicalized and validated as git repos, so a bare `leogit` (or a non-repo arg) just launches/focuses the window.

- [x] **Per-repo pull/push badges + tiered background sync.** Each repo picker row shows `↓ N` (behind) / `↑ N` (ahead) badges reusing the header Pull/Push glyphs, so you can see which repos need attention without opening them. A new `repoSyncScheduler` keeps them fresh on a recency-decaying cadence (active repo: existing 30 s auto-fetch + 2 s poll; next 4 recents every 2 min + throttled on refocus; next 5 every 5 min; next 10 every 10 min; the tail only when switched to), sliced from a persisted most-recently-opened list (`ReposState.recent_repos` + `recentRepos` store + `recordRecentRepo`). Backend `repo_sync_status` (best-effort fetch + headers-only ahead/behind, reusing the extracted `first_remote` / `remote_tracking_ahead_behind` helpers) feeds the `repoSync` store; the active repo's counts are pushed in from the status poll. As a side effect the **app now fetches the active repo on window refocus** (previously only on the 30 s timer), so the Pull button's behind badge surfaces as soon as you return to the app.

- [x] **Persisted sort toggles (repo picker + Clone dialog).** Both clock ↔ A→Z sort toggles now default to recency ("last modified") and survive restarts. A dedicated `reposState` store owns `repos-state.json`: `repoSortMode` / `cloneSortMode` writables, `setRepoSortMode` / `setCloneSortMode` setters that persist via a single read-modify-write `patchReposState` (so a sort mode never clobbers `last_opened_repo` / `last_clone_dir`), and `hydrateReposState` to seed the toggles at startup. Backend `ReposState` gained `repo_sort_mode` / `clone_sort_mode` (`Option<String>`, `#[serde(default)]`). The session-only sort flag in `repoActivity` was removed; `MainLayout`'s local `persistReposState` was folded into the store.

- [x] **Fresh-repo (unborn HEAD) support.** A brand-new `git init` repo with no commits yet no longer errors. Committing clears the index with `git reset -- .` (the pathspec form, which works on an unborn HEAD) instead of `git reset HEAD`, so the very first commit goes through; opening History short-circuits to an empty list (via a `has_commits` check) instead of surfacing git's "does not have any commits yet" fatal, and `CommitList` renders a "No commits yet" empty state. Covered by Rust regression tests in `commands::git::tests`.
- [x] **Clone a repository.** A clone icon beside the repo-switcher filter opens a two-tab dialog (`CloneOverlay.svelte`): **GitHub** lists your `gh repo list` repos (filterable, `Private` badges) and clones the pick via `gh repo clone` (inherits gh auth); **URL** clones a git URL / `owner/name` shorthand via `git clone` (`GIT_TERMINAL_PROMPT=0`). The destination defaults to `last_clone_dir` → first scan path → `~/Dev`, with a live `parent/repo` path preview. On success it remembers the folder, adds the repo to the in-memory list, and opens it — no rescan/restart. Backend: `git::clone_repo`, `gh::gh_repo_list`, `gh::gh_clone` (shared `prepare_clone_target` helper); `ReposState.last_clone_dir` persisted via read-modify-write so it never clobbers `last_opened_repo`.
- [x] **Shift+click multi-select for file rows and checkboxes.** Shift+click on a file's row body extends a visual multi-row selection from the row-anchor to the clicked row (and still activates the clicked row's diff); pressing Space on a focused row in that multi-selection bulk-toggles every selected row's inclusion. Shift+click on a checkbox sets every checkbox in the range from the checkbox-anchor to the clicked one to whatever the clicked checkbox is about to become (Finder / Gmail semantics). Row-anchor and checkbox-anchor are independent so the two gestures don't bleed into each other; anchors prune on commit/refresh.
- [x] **Undo last commit.** Right-click the top commit → "Undo last commit…" runs `git reset --mixed HEAD~1`, then pre-fills the composer with the undone commit's message (and Co-Authored-By trailers) so re-committing is one click away. Gated to unpushed commits when an upstream is resolvable.
- [x] **Amend last commit.** Right-click the top commit in History → "Amend last commit…"; composer pre-fills summary / description and preserves Co-Authored-By trailers, shows a "your changes will modify your most recent commit / Stop amending" notice, swaps the button label to "Amend commit", and allows committing with no file selection.
- [x] **Publish to GitHub.** When a repo has no remote (`RepoStatus.has_remote === false`), the Push split-button becomes "Publish" and its dropdown shows a single "Publish to GitHub…" item. The dialog ([PublishRepository.svelte](tauri-app/src/lib/components/PublishRepository.svelte)) is GitHub.com-only (no Enterprise tab) with Name / Description / "Keep this code private" (private by default); confirming runs `gh repo create --source --remote origin --push` (`gh::gh_publish_repo`), inheriting `gh` auth. The next status refresh flips `has_remote` and the button reverts to Push.
- [x] **Publish branch.** When the repo has a remote but the current branch has no upstream (`hasRemote && !hasUpstream`), the Push split-button becomes **"Publish branch"** (upload icon) with a single "Publish branch" dropdown item, matching GitHub Desktop. It reuses `handlePush` — which already passes `--set-upstream` when `!hasUpstream` — so one click creates the branch on the remote and starts tracking; the next status refresh flips it to a plain Push. The header's **Pull button now only renders when the branch has an upstream** (nothing to pull from an unpublished branch), so the publish state shows just the one affordance. Presentation-only change in [Header.svelte](tauri-app/src/lib/components/Header.svelte); the backend `push` already accepted `set_upstream`.
- [x] **Force-push (with lease).** Exposed in the push button split-dropdown, behind a confirmation dialog. Backend already accepted `force_with_lease`; the UI now drives it. The dropdown item now appears **only when the branch has diverged** (ahead AND behind), instead of always showing and merely disabling on no-upstream.
- [x] **Push / Pull buttons render ahead / behind counts.** "Push (3)" / "Pull (1)" with tabular numerics.
- [x] **Reusable `ContextMenu` primitive.** Used by the commit right-click menu and the push split-dropdown; unlocks future file-row / branch-row / commit-row context menus.
- [x] macOS PATH fix at startup so `claude` / `gh` / brew binaries resolve when launched from Finder.
- [x] **Windows: kill console-window flicker + PowerShell terminal default.** Every `git` / `gh` / `claude` spawn sets `CREATE_NO_WINDOW` (via `commands/process.rs`), so the GUI-subsystem release build never flashes a `cmd` box during the 2s status poll or on actions. The embedded terminal now ignores the Unix-only `$SHELL` on Windows (which could point at a non-resolvable POSIX path when launched from Git Bash) and prefers `pwsh.exe` → `powershell.exe` → `cmd.exe`, mirroring Windows Terminal's default shell.

## What's next

- [ ] **Brighten the line-selection dot.** The current `selection-dot` is too dim against `--bg-primary`; bump alpha or use `--border-active` outline even when unselected.
- [ ] **AI generation must respect line-level selection.** Currently `getSelectedDiff` sends full file diffs for every selected file. It should use `diffApi.generatePatch(repoPath, fileDiff, selection)` per file so the AI only sees the lines actually selected. Requires propagating per-file `DiffSelection` (already in `repoState.diffSelection`) into the generate flow.
- [ ] **Commit composer auto-resize on focus.** When the user focuses the message section, grow it temporarily so summary + description are both visible. Optionally allow manual resize via `Ctrl+Shift+Arrow`.
- [ ] **AI-generated long messages scroll to start.** After Generate, scroll the description textarea to the top (currently shows the tail of long outputs). A subtle scrollbar or `…` indicator would also help.
- [ ] **Settings panel scrolling.** The Settings modal body needs `overflow-y: auto` to be reachable on smaller windows — currently it can clip below `max-height: 85vh`.
- [ ] **Settings re-arm intervals on save.** `fetch_interval_ms` and `auto_fetch` only take effect on app restart today; saving Settings should clear/restart `fetchInterval` immediately.
- [ ] **Re-focusing the terminal.** After tabbing back into the terminal, the borders highlight but keystrokes are dropped until the user clicks. Need to call `term.focus()` from xterm.js when the container regains focus.
- [ ] **Terminal key passthrough.** Space, `Ctrl+X`, and other control sequences are intercepted by global shortcuts. Gate the global keydown handler off when the terminal is focused.
- [ ] **Internally-stashed files exclusion.** Verify that when a file is deselected (in `userDeselected`) it never makes it into the commit even if `git status` reports it as staged externally.
- [ ] **"Create GitHub Project" action.** Surface `gh project create` (or wrap the gh GraphQL call) as a one-off action — the auth check stays wired (`ghApi.checkAuth` + `gh.rs::check_auth`), so the gating is already there.
